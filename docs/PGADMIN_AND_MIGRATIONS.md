# Почему не видно таблиц в pgAdmin

## Причина

Таблицы создаются только после успешного запуска миграций Alembic (`alembic upgrade head`). Если миграции не выполнялись к той базе, к которой вы подключены в pgAdmin, таблиц не будет.

## Что проверить

1. **Та же база, что и у приложения**  
   В pgAdmin вы должны быть подключены к той же PostgreSQL, что указана в переменной **DATABASE_URL** у сервиса на Railway. Если подключились к другой базе (локальной или другому проекту), таблиц там не будет.

2. **Схема public**  
   Таблицы создаются в схеме **public**. В дереве: ваша БД → Schemas → public → Tables.

3. **После деплоя**  
   На Railway миграции запускаются при старте сервиса (`startCommand`: сначала `alembic upgrade head`, затем приложение). Сделайте редеплой и дождитесь успешного старта — затем обновите список таблиц в pgAdmin (правый клик по Tables → Refresh).

## Запуск миграций вручную

Если нужно применить миграции к своей копии БД (например, к той, что смотрите в pgAdmin):

```bash
set DATABASE_URL=postgresql://user:password@host:5432/dbname
alembic upgrade head
```

Подставьте в `DATABASE_URL` хост, пользователя, пароль и имя базы из pgAdmin (или скопируйте строку из Railway → Variables → DATABASE_URL).
