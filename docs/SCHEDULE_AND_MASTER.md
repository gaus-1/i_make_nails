# Расписание и панель мастера

## Роли (MASTER_TELEGRAM_IDS и ADMIN_TELEGRAM_IDS)

- **MASTER_TELEGRAM_IDS** — Telegram ID мастера (через запятую, если несколько). В боте у этих пользователей отображается кнопка «Панель мастера»; они рассылают ссылку на бота клиентам, клиенты сами записываются.
- **ADMIN_TELEGRAM_IDS** — кто может вызывать API мастера (расписание, клиенты, настройки). Обычно сюда входят и мастер, и разработчик. Мастер в обоих списках; разработчик только в ADMIN — доступ к панели мастера по API есть, но кнопки «Панель мастера» в боте нет (доступ скрыт).

Пример: `MASTER_TELEGRAM_IDS=1349219064`, `ADMIN_TELEGRAM_IDS=1349219064,963126718`.

## Первый деплой

При деплое на Railway миграции применяются автоматически (release-команда или старт контейнера: `alembic upgrade head`). После первого деплоя в БД нужно создать запись мастера и хотя бы одну услугу с расписанием, иначе мини-приложение и бот будут возвращать ошибки. Данные можно добавить через SQL или скрипт (например, `INSERT INTO master (telegram_id, display_name, timezone) VALUES (...);` и т.д.).

## Рабочие окошки

- **Время приёма:** с 8:00 до 22:00 (настраивается в расписании мастера).
- **Длительность окошка:** 1,5–2 часа — задаётся у каждой услуги (`duration_minutes`). Свободные слоты считаются с шагом по длительности выбранной услуги.
- **Выходной:** воскресенье. В таблице `work_schedule` не добавляют строки с `day_of_week = 6` (0 = понедельник, 6 = воскресенье).

Мастер выставляет расписание через **PATCH /api/miniapp/master/settings**, в теле передаёт `work_schedule`: массив `{ day_of_week, time_start, time_end }`. Пример для Пн–Сб 08:00–22:00 (время локальное, например Europe/Moscow):

- Пн (0): 08:00–22:00
- Вт (1): 08:00–22:00
- …
- Сб (5): 08:00–22:00
- Вс (6) не включать.

## Чёрный список

- В панели мастера: **GET /api/miniapp/master/clients** — список клиентов с полем `booking_allowed`.
- Запрет онлайн-записи: **PATCH /api/miniapp/master/clients/{client_id}** с телом `{ "booking_allowed": false }`.
- Повторное разрешение: `{ "booking_allowed": true }`.

Клиенты с `booking_allowed: false` при попытке создать запись получают ответ 409 и сообщение о недоступности онлайн-записи.
